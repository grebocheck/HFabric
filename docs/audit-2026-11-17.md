## Канонічна робота з параметрами

`frontend/src/lib/preferences.ts` містить один механізм збереження:
типізовані workspace stores, versioned JSON, валідація полів, синхронний запис
у setter, React subscription через `useSyncExternalStore`, синхронізація між
вкладками браузера і fallback у пам'ять при недоступному localStorage.

`frontend/src/settings/workspacePreferences.ts` задає defaults і правила
доменів; `imagePreferences.ts` використовує чинний parser Image Composer і
мігрує старий формат без втрати touched-полів. `runtimeDraft.ts` відновлює
чернетку Settings тільки для полів, які приймає поточна server schema.

Підключені Images, Edit, Video, Chat, Voice, offline Voice, TTS,
Transcription, Code, RAG, Gallery/Video History, Notes, Models/Downloads,
Hugging Face/Civitai browsing, Settings, System, Mask Editor і навігація/тема.
Старі ключі Image Composer, Chat defaults, теми, workspace та Civitai NSFW
мігруються при першому читанні.

Виправлення причин скидання:

- Voice зберігає вибір моделі, preset та окремі `draft`/`confirmed` значення.
  Перезавантаження відновлює незастосовані tuning-параметри з індикатором
  unsaved. Polling і відповіді старих Apply-запитів зберігають новіші правки.
  Застосовані параметри й далі зберігає backend у `voice-settings.json`.
- Chat зберігає всі sampling-поля, включно із seed=0, top_p/top_k, min_p,
  repeat penalty, stop та system prompt. Відновлюється остання розмова;
  її початкове завантаження більше не перезаписує локальну чернетку.
  Явний вибір іншої розмови застосовує параметри цієї розмови.
- Edit не очищує збережений model ID до завершення завантаження каталогу
  і не застосовує family defaults поверх відновлених параметрів.
- Settings зберігає незастосовані зміни, очищує їх після підтвердження Save
  або Revert та залишає нові правки, зроблені під час запиту.
- Параметри Video/TTS/Transcription, фільтри й текстові чернетки відновлюються
  тим самим механізмом. Стан запитів, live/recording/PTT, файли, маски та
  тимчасові upload tokens залишаються в життєвому циклі відповідних операцій.

Ці браузерні параметри належать поточному origin/profile; між пристроями
вони не синхронізуються. Для застосування Voice tuning і server Settings
залишаються явні Apply/Save; routing Voice зберігає поточний autosave.

## Встановлення та межі перевірки

Frontend dependencies встановлено локально. Windows заблокувала
`libportaudio64bit.dll` під час спроби оновлення робочого `.venv`; після
перерваного встановлення відновлено відсутні пакети, `pip check` проходить.
Нові hashed Python graphs встановлено й перевірено в
`.tmp/dependency-venv`. Для import smoke звідти використано встановлені
torch/torchvision/torchaudio та Nunchaku з робочого середовища.

Після зупинки процесів, що використовують `.venv`, оновлення Windows CUDA
development-середовища можна завершити так:

```powershell
.\.venv\Scripts\python.exe -m pip install --require-hashes -r backend/requirements-dev.lock -r backend/requirements-gpu.lock
.\.venv\Scripts\python.exe -m pip check
```

Реальну генерацію моделей, апаратні latency/VRAM, чисту ROCm/MPS-інсталяцію
і нову torch/Nunchaku ABI-комбінацію не перевіряли.
